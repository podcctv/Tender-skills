# 中国政府采购投标文件格式与编制规范

## 1. Skill 目标

本 Skill 用于中国政府采购项目投标文件、响应文件、技术方案、商务文件、资格文件的编制与审查。

核心目标：

1. 优先满足采购文件规定的格式和实质性要求；
2. 防止因签字、盖章、格式、文件组成、上传方式等问题造成资格审查或符合性审查失败；
3. 在采购文件未明确排版规范时，自动采用统一、正式、适合政府采购评审阅读的默认版式；
4. 建立“采购要求—投标响应—证明材料—页码位置”的完整证据链；
5. 使投标文件不仅形式规范，还能够直接对应资格审查、符合性审查及评分标准；
6. 禁止虚构资质、案例、参数、人员、证书、检测报告和承诺。

---

# 2. 最高原则：采购文件优先

处理任何政府采购项目时，不得直接套用固定标书模板。

必须首先解析采购文件。

格式和编制规则优先级原则：

法律法规及国家强制性要求

>

采购公告、采购文件、招标文件

>

澄清文件、更正公告、答疑文件

>

投标人须知及须知前附表

>

采购文件规定的投标文件格式

>

电子交易平台上传及签章要求

>

本 Skill 默认格式规范

如果后发布的澄清、更正文件修改了原采购文件，以有效的最新文件为准。

若采购文件已经明确：

* 字体
* 字号
* 页边距
* 页码
* 文件组成
* 章节顺序
* 正副本数量
* 是否分册
* 文件命名
* 签字要求
* 盖章要求
* 骑缝章要求
* 密封要求
* CA 签章要求
* PDF格式
* 上传方式
* 文件大小
* 是否允许压缩包
* 是否要求单独上传报价文件
* 是否要求资格文件单独上传

必须严格执行采购文件规定。

不得使用本 Skill 的默认规范覆盖采购文件规定。

# 4. 优先检查可能导致无效投标的要求

开始写技术方案之前，必须先检查资格审查和符合性审查。

重点识别：

### A级：无效投标/资格失败风险

例如：

未按要求签字；

未按要求盖章；

法人签字缺失；

授权代表无有效授权；

投标函未签章；

报价表未签章；

投标有效期不满足；

交付期不满足；

质保期不满足；

未提供要求的资格证明；

未提供中小企业声明函；

未按要求提供联合体协议；

报价超过最高限价；

漏报采购内容；

出现选择性报价；

核心产品不符合要求；

未响应实质性条款；

未响应“★”条款；

文件未按要求加密；

未按规定上传；

要求分文件上传而错误合并；

要求分别上传资格、商务技术、报价文件而未分别上传。

A级问题优先级最高。

发现A级风险时必须明确提示：

【高风险：可能导致无效投标】

不得仅继续优化文字内容而忽略该风险。

# 5. 原始投标格式不得随意修改

采购文件提供：

投标函；

开标一览表；

报价明细表；

法定代表人身份证明；

法定代表人授权委托书；

资格声明函；

中小企业声明函；

残疾人福利性单位声明函；

监狱企业证明；

商务响应表；

技术响应表；

偏离表；

项目负责人表；

项目团队表；

业绩表；

售后服务承诺；

廉政承诺；

诚信承诺；

政府采购政策相关表格；

其他规定格式。

原则：

不得擅自删除字段；

不得擅自改变字段含义；

不得擅自合并采购文件规定的表格；

不得擅自取消签字栏；

不得擅自取消盖章栏；

不得改变必须填写的声明文字；

不得将采购文件要求的固定格式改造成完全不同的自定义格式。

可以在采购文件允许情况下：

调整列宽；

调整行高；

分页；

增加必要附页；

增加“证明材料页码”等辅助列。

如果不能确定是否允许修改：

优先保持原格式。

# 6. 投标文件推荐总体结构

如果采购文件已经规定目录结构：

完全按照采购文件执行。

如果采购文件没有明确规定，可采用：

封面

目录

第一部分 资格证明文件

第二部分 投标报价文件

第三部分 商务响应文件

第四部分 技术响应文件

第五部分 项目实施及服务方案

第六部分 企业综合实力证明材料

第七部分 政府采购政策相关文件

第八部分 其他资料

附件

不得为了“看起来专业”随意改变采购文件要求的文件顺序。

采购文件未提供封面模板时，可采用：

项目名称：

项目编号：

标项名称/包号：

投标文件

投标人：

法定代表人或授权代表：

日期：

封面原则：

正式；

简洁；

不使用复杂背景；

不使用大面积彩色装饰；

不放置与项目无关宣传语；

不添加未经要求的采购人 Logo；

避免商业宣传册式设计。

# 8. 默认纸张及页面规范

只有采购文件没有规定时，使用以下默认值。

纸张：

A4，210mm × 297mm。

方向：

正文纵向。

大型参数表、设备清单、进度计划等必要情况下可以使用横向页面。

默认页边距建议：

上：2.5 cm

下：2.5 cm

左：2.8 cm

右：2.5 cm

装订线：

采购文件未要求时无需设置。

如果纸质文件胶装且页数较多，可适当增加左边距。

---

# 9. 默认字体规范

采购文件未规定字体时采用统一、常见、兼容性好的字体。

### 一级标题

三号黑体

加粗

段前适当留白

示例：

第一章 项目总体理解

### 二级标题

小三号黑体

加粗

示例：

1.1 项目背景

### 三级标题

四号黑体

加粗

示例：

1.1.1 建设目标

### 四级标题

小四号黑体或小四号宋体加粗。

### 正文

小四号宋体。

西文、数字可以使用：

Times New Roman

或者与中文正文保持统一字体。

整份文件必须保持一致。

---

# 10. 默认正文排版

正文建议：

字号：小四号；

字体：宋体；

行距：1.5倍；

首行缩进：2个字符；

段前：0；

段后：0～6磅；

两端对齐。

原则：

不要大量使用空格实现对齐；

不要连续使用回车实现分页；

使用正式分页符；

标题避免出现在页面最后一行；

尽量避免表格标题和表格主体跨页分离。

---

# 11. 默认表格规范

表格正文建议：

五号宋体。

内容较多时：

允许使用小五号。

原则上不建议小于小五号。

表头：

五号黑体或宋体加粗。

表格要求：

边框清晰；

文字垂直居中或顶部对齐；

数字格式统一；

单位统一；

参数值与单位之间格式统一；

避免单元格内容被截断；

不得因压缩表格造成内容无法阅读。

长表格跨页时：

必须重复标题行。

---

# 12. 图片、截图和证明材料规范

所有图片必须保证最终 PDF 中可清晰辨认。

包括：

营业执照；

资质证书；

检测报告；

认证证书；

合同；

中标通知书；

验收报告；

软件截图；

系统界面；

设备照片；

拓扑图；

技术架构图；

项目团队证书。

不得：

严重压缩；

模糊；

拉伸变形；

遮挡关键信息；

剪掉证书名称；

剪掉证书编号；

剪掉有效期；

剪掉签章；

剪掉合同双方名称。

证明材料建议在附近注明：

证明材料名称：

证明对象：

对应评分项：

关键证明内容：

原件页码/附件页码：

---

# 13. 页码规范

采购文件未规定时：

正文从目录之后或正文第一页开始连续编码。

采用：

1、2、3……

建议：

页脚居中。

大型标书建议使用：

第 X 页 / 共 Y 页

或者：

— X —

资格、商务、技术如果分别成册，可以分别编号。

不得出现：

大量重复页码；

缺页；

页码与目录严重不一致；

插入附件后目录页码未更新。

---

# 14. 目录规范

超过约30页的投标文件必须建立自动目录。

大型投标文件建议至少建立三级目录。

例如：

1 项目总体理解

1.1 项目背景

1.2 建设目标

1.3 建设范围

1.4 需求分析

2 总体技术方案

2.1 总体架构

2.2 系统架构

2.3 网络架构

2.4 安全架构

PDF最终文件建议保留：

书签；

目录跳转；

清晰章节层级。

但不得因此破坏采购平台要求的PDF格式。

---

# 15. 技术参数响应规范

所有技术要求原则上逐条响应。

推荐技术响应表：

序号

采购文件要求

投标响应

偏离情况

证明材料

证明页码

不得简单大量填写：

“满足。”

“完全满足。”

“响应。”

对于重要指标必须写清：

投标产品实际参数；

功能；

性能；

实现方式；

型号；

版本；

证明文件。

例如采购要求：

支持不少于100路视频接入。

正确响应方式：

所投平台支持≥100路视频并发接入，本项目配置支持128路视频接入，详见《产品技术说明书》第XX页。

不要仅写：

完全满足。

# 16. ★号及实质性指标

出现以下表达时必须重点处理：

★

▲

实质性要求

必须

不得

应当

不允许偏离

否则投标无效

必须单独建立：

《实质性条款响应检查表》

每一条至少包含：

采购要求；

投标响应；

证明材料；

所在页码；

是否满足；

风险状态。

不得遗漏。

# 17. 商务响应规范

商务条件建议逐项响应。

包括：

交付期限；

实施地点；

付款方式；

质保期；

售后服务；

培训；

验收；

知识产权；

保密要求；

人员要求；

运维期限；

服务响应时间；

备品备件；

违约责任。

禁止将不确定内容自动填写为“完全满足”。

如果招标文件要求与企业实际能力存在冲突：

必须标记：

【待投标人确认】

# 18. 评分标准驱动编制

如果采用综合评分法：

必须根据评分标准建立：

《评分响应索引表》。

建议字段：

评分大项

评分小项

分值

评分要求

投标响应章节

证明材料

页码

预计得分

证据完整度

风险

对于每个评分项形成：

评分要求
→
响应内容
→
证明材料
→
页码定位

禁止出现：

方案写得很多但评分项找不到；

有证书但没有对应评分条款；

有案例但没有合同关键页；

有人员证书但无法证明劳动关系；

评分需要验收证明但只提供合同。

# 19. 技术方案写作原则

技术方案不能只写产品介绍。

必须围绕：

采购需求；

项目目标；

建设内容；

业务场景；

评分标准；

验收要求；

实施要求。

方案应优先体现：

需求理解；

总体设计；

详细设计；

设备部署；

系统部署；

网络设计；

数据设计；

安全设计；

接口设计；

系统集成；

实施计划；

项目组织；

质量保障；

安全保障；

测试方案；

培训方案；

试运行方案；

验收方案；

运维方案；

售后方案；

应急保障。

如果评分标准对：

总体方案；

现场实施方案；

项目实施方案；

培训方案；

运维方案；

售后方案；

应急方案；

演示方案

分别评分，则必须分别形成独立章节。

不得简单合并成一个“实施及售后服务方案”。

# 20. 企业资料及证明材料原则

任何涉及：

企业资质；

企业荣誉；

知识产权；

软件著作权；

专利；

认证；

项目案例；

合同金额；

项目经理；

技术人员；

学历；

职称；

证书；

社保；

检测报告；

厂家授权；

产品认证

的信息：

只有用户提供证据或采购文件已有明确证据时才能写入正式投标文件。

没有证据时使用：

【待提供】

【待核实】

【需投标人确认】

禁止模型自行编造。

# 21. 投标报价文件特殊规则

报价属于高风险内容。

未经明确授权：

不得自行推测最终报价。

不得自行填写最终投标总价。

不得自行承诺折扣率。

不得自行修改税率。

不得改变采购文件规定的报价口径。

报价必须检查：

总价与分项价关系；

数量 × 单价；

含税/不含税；

税率；

大写金额；

小写金额；

单位；

总价；

最高限价；

单项最高限价。

如果存在计算差异：

必须标记并提示。

---

# 22. 分册及电子文件

如果采购平台要求：

资格文件；

商务技术文件；

报价文件

分别上传：

必须分别生成。

不得因为制作方便合并成一个PDF。

如果采购文件要求报价信息不得出现在技术文件：

技术文件中不得出现：

投标总价；

单价；

折扣率；

报价清单；

其他可能泄露报价的信息。

---

# 23. 电子签章与纸质签章

签字、盖章规则必须完全按照采购文件。

不得自行假设：

“扫描件公章一定有效”

或者：

“电子签章可以替代所有签字”。

必须读取项目具体要求。

常见检查点：

投标人公章；

法定代表人签字或签章；

授权代表签字；

CA电子签章；

联合体各方签章；

报价表签章；

投标函签章；

声明函签章；

骑缝章；

逐页盖章。

如果采购文件没有要求逐页盖章：

不得自行认定必须逐页盖章。

---

# 24. 纸质投标文件

如果项目仍要求纸质投标：

检查：

正本数量；

副本数量；

是否需要电子U盘；

正副本标识；

装订方式；

是否允许活页装订；

是否要求胶装；

封套；

外包装；

密封；

封口盖章；

递交地址；

递交截止时间。

采购文件没有要求时：

不得自行创造“必须胶装”“必须骑缝章”等硬性要求。

---

# 25. 不得把行业习惯冒充法律要求

以下内容通常只能作为默认排版建议，而不能描述为全国统一强制法规：

“小四宋体”

“1.5倍行距”

“A4纸”

“左边距2.8厘米”

“一级标题三号黑体”

# 26. 法规适用范围识别

本 Skill 默认针对：

政府采购货物类项目；

政府采购服务类项目；

与货物、服务采购相关的软件、信息化、系统集成、设备采购项目。

如果属于：

政府采购工程招标投标；

施工招标；

工程建设项目；

依法必须招标的工程相关货物或服务；

必须进一步判断是否适用《中华人民共和国招标投标法》及其配套制度。

《中华人民共和国政府采购法实施条例》

《政府采购货物和服务招标投标管理办法》（财政部令第87号）

修订草案；

征求意见稿；

尚未实施的新规

必须明确标记：

【尚未生效】

# 28. 防止串标及文件来源风险

不得为多个参与同一项目竞争的投标人制作实质内容异常一致的投标文件。

不得协助规避串通投标识别。

不得复制竞争对手文件并伪装成独立编制。

如果发现：

不同投标人项目人员相同；

文件内容异常一致；

报价存在规律性；

资料疑似相互混用

必须标记高风险。

# 30. 输出风险状态

完成投标文件后必须输出《投标文件风险清单》。

风险状态统一使用：

🔴 高风险
可能造成资格审查失败、符合性审查失败或无效投标。

🟠 中风险
可能造成扣分或证明材料不充分。

🟡 待确认
缺少投标人信息、证明材料或采购人澄清。

🟢 已满足
已有明确响应和完整证据。

不得为了让报告看起来完整而将未知事项自动标记为“满足”。

# 33. 最终原则

政府采购投标文件编制遵循：

合规优先于美观。

采购文件优先于模板。

实质响应优先于篇幅。

评分标准优先于宣传内容。

证据优先于描述。

准确优先于夸张。

可核验优先于“写得好看”。

遇到采购文件明确要求与本 Skill 默认规则冲突：

永远优先执行采购文件。

遇到无法确定的问题：

标记风险，不自行假设。

# 34. 静默格式下的版式预设与证据门禁

当采购文件、澄清文件、官方模板和交易平台均未明确版式时，可以选择一个默认版式预设；选择结果必须在《投标文件格式要求清单》中标记为“默认建议”，不能写成采购文件强制要求。

候选 fallback 预设（均须标记为“默认建议”）：

| 预设 | 适用场景 | 默认取向 |
| --- | --- | --- |
| `standard-bid` 标准投标版 | 普通综合响应 | 纵向正文、稳定标题层级、清晰页码和表格 |
| `formal-binding` 正式装订版 | 需要纸质归档或正式装订但文件未规定细节 | 预留装订空间、正式封面、目录和分册提示 |
| `wide-table` 宽表格版 | 参数、清单、接口或评分矩阵较多 | 对宽表采用局部横页或横向表格排布 |
| `compact-review` 紧凑评审版 | 仅在用户明确选择且不触及硬性格式时参考 | 减少装饰和空白；不得用压页改变字号、边距或可读性 |
| `illustrated` 图文方案版 | 仅在用户明确选择且不触及硬性格式时参考 | 图文并重；图示不得替代实质响应 |

`standard-bid`、`formal-binding` 和 `wide-table` 可用于填补静默项；`compact-review`、`illustrated` 只保留为参考策略，不得自动套用。任何预设都不能覆盖：纸张、字体、字号、行距、页边距、目录/章节顺序、固定响应表、页码、签字盖章、骑缝章、文件拆分、文件命名、加密、上传、解密和平台制作要求。主题色、封面图和装饰性元素不得破坏固定表格、评审可读性或响应顺序。

格式审查同时建立“来源—证据—页码”索引：

- 固定表格、资格材料、参数响应、评分证据和承诺函都应有来源或材料编号；
- 原文在可读范围内未提及、解析流程未提取、来源本身不可读分别记录为“原文未提及”、`未提取到`、`待核实`，三者都不能改写成“无要求”；
- 电子文件风险与纸质装订、密封、现场签到等线下动作分开检查；
- 自动重复、错字或逻辑告警只作为人工复核入口，不能单独推出废标结论；
- 在所有明确要求核对完毕后，才执行本节的默认版式建议。
